# Translation conventions

English and Bangla catalogs in `messages/` are the translation source of truth.
Registries contain structure, stable identifiers, option values, and search terms,
not bilingual display text. Stored agriculture request snapshots intentionally
retain bilingual labels for historical compatibility.

## UI keys

Use `feature.purpose.camelCaseKey`, for example:

- `agriculture.requestForm.signInNotice`
- `construction.serviceDetail.listingsFor`
- `projects.packages.noInvitations`
- `common.actions.view`

Names describe a purpose, not the English sentence. Do not use hashes, truncated
sentences, snake_case, or numbered collision suffixes. Shared keys belong in
`common` only when their meaning is shared. Otherwise keep them with their feature.

Stable domain identifiers are exceptions: service/sector/category slugs, agriculture
field names, numeric option indices, and status enums keep their existing spelling.
Never rename submitted option values or stored identifiers to match UI conventions.
Arrays rendered through `t.raw`, such as policy items, retain numeric indices.
Agriculture option messages use numeric **object properties**, allowing next-intl
to type-check paths such as `options.0.label` without changing their key paths.

`scripts/i18n/key-migrations.json` records old keys and their canonical replacements,
including merged aliases. It is migration history, not a second catalog or a runtime
alias resolver. Do not import it into app code or count its entries as live usage.
The companion migration script only handles key moves, not subsequent ICU changes.

## Dynamic keys and counts

- Prefer namespace-scoped translators for namespace-relative keys.
- Use catalog-derived types or registry-backed key helpers for dynamic keys.
- Validate unknown runtime values before translation; preserve explicit fallbacks.
- Do not bypass message typing with `as never`, `any`, or broad string casts.
- Import catalog types with `import type` so client code cannot bundle the catalogs.
- App server code uses `src/i18n/catalog.ts`; only standalone scripts may import
  the shared `catalog-data.ts` implementation directly.
- Translate the complete count with ICU: `t(key, { count })`. Do not concatenate
  a number and a plural label. This lets each locale place and format its number.

## Verification

Run `bun run typecheck`, `bun run lint:check`, and `bun run test:unit` after edits.
The audit parses translator bindings and lexical scopes, checks literal keys and
template families, and ignores arbitrary quoted text and migration mappings.
Registry/status tests cover dynamic helpers the scanner cannot evaluate statically.
Locale parity, ICU arguments, count formatting, server boundaries, and request
snapshot shape also have regression coverage.

For workflow changes, run `bun run db:test:setup` and `bun run test:integration`.
Check the affected pages in both locales before shipping.
